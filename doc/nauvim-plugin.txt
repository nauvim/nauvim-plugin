INSTALLATION					       *nauvim-plugin-install*

Requires Neovim v0.12.6.  Use the latest nauvim-core and nauvim-plugin.
Install this repository with a plugin manager or add it to 'runtimepath'. >lua

    vim.opt.runtimepath:prepend("/absolute/path/to/nauvim-plugin")
<
The root module exposes `client`, `filesystem`, `http`, `clipboard`, and
`["local-forward"]`. >lua
    local nauvim = require("nauvim-plugin")
    local forward = nauvim["local-forward"]
<
Nauvim registers itself automatically. See |nauvim-plugin-client|.

CALLS AND ERRORS					 *nauvim-plugin-calls*

Each operation takes an `{opts}` table with the documented fields.
nauvim-core validates arguments and ensures its RPC responses conform to the
specification.  The plugin sends the stored client ID followed by the fields
as positional RPC arguments.

The specification denotes a request result as the tuple `(ret, err)`.  In Lua,
requests return these as two separate values in that order. >lua
    local http = require('nauvim-plugin.http')
    local ret, err = http.get_port({ handle = handle })
<
Test `err == nil` for the absence of a request error.  Request errors are
returned as nonempty strings.  A `nil` result with no error is valid, such as
when a pending `get_port()` is cancelled.

Notifications return `nil` and have no RPC response.  `clear()`,
`http.focus_webview()`, and `clipboard.copy()` ignore send failures.
`client.connect()` displays a send failure and keeps the UI attached.

Without a selected RPC destination, requests, notifications and clipboard copy
callbacks do nothing.  Requests return `nil, nil`.  Other calls return `nil`.
Calls do not wait for registration and are not replayed later.  Clipboard
paste callbacks always supply no text, regardless of the selected destination.

Host permissions				     *nauvim-plugin-host-permissions*

nauvim-core checks the selected host's policy for `filesystem.copy()`,
`http.serve_file()`, `http.open_webview()`, `local-forward.open_tcp()`,
`local-forward.open_socket()`, and `clipboard.copy()`.  Omitted permissions
grant no access to these operations.  A denied request returns `nil, err`.
A denied notification reports an error in the Nauvim client and sends no RPC
response.  Handle queries, cleanup, `http.focus_webview()`, and client calls
follow their usual rules independently of these permissions.

Specification types ~

- `bool` and `int` correspond to Lua `boolean` and `integer`.  The unsigned
  types `u16` and `u32` specify the ranges 0 to 65535 and 0 to 4294967295.
  Lua represents both with ordinary numbers.
- `list[T]` describes a sequence, `dict[K, V]` describes a map, and
  `func(T) -> U` describes a function.
- `T | U` accepts either type, with repeated alternatives counting once.
  `"+" | "*"` accepts only the two quoted values.

Every RPC `string` must be valid UTF-8 without NUL or an initial U+FEFF.
U+FEFF is allowed elsewhere in the string.  This applies to nested keys and
values, clipboard text and errors in RPC responses.  The separate `bytes` type
can carry arbitrary byte sequences.

Resource handles ~

Resource handles identify asynchronous work and its associated resources.
Receiving a handle does not establish that work has completed or succeeded.
Later failures are displayed in the client according to the operation's rules.
`get_port()` waits for binding and returns its outcome, including errors.

Handles address resources in the currently selected client.  Handles can be
reused and an old value addresses whatever resource currently has that value.
Detachment cleans up attachment resources.

Path arguments						 *nauvim-plugin-paths*

Client paths (`{client_file}` and `{client_socket_path}`) use Nauvim's process
temporary directory as their base.  The core removes leading slashes, resolves
paths and symlinks, and accepts only strict descendants of that directory.
Client paths use POSIX semantics and are not URL-decoded.  The plugin passes
their strings unchanged to the client.

Relative `{host_file}` and `{host_socket_path}` values use the effective host
Neovim current directory at the time of the call, including |:lcd| and |:tcd|.
The plugin expands them with `fnamemodify(path, ':p')` before transmission.
Host-side filesystem operations resolve symlink targets.

LOCAL FORWARDING				 *nauvim-plugin-local-forward*

Use `require('nauvim-plugin.local-forward')`.

open_tcp({opts})		      *nauvim-plugin.local-forward.open_tcp()*
    Requests a forward from client IPv4 loopback (127.0.0.1) to a destination
    reached from the host.

    Parameters: ~
      • {opts}  (`table`) Forwarding options.
                • {client_port} (`integer`) 0 to 65535.  Zero requests an
                  available port.
                • {host_addr} (`string`) Address reached from the host.
                • {host_port} (`integer`) 1 to 65535.

    Return (multiple): ~
      • (`integer?`) Forwarding handle.
      • (`string?`) Request error.

open_socket({opts})		   *nauvim-plugin.local-forward.open_socket()*
    Requests a Unix domain socket forward.

    Parameters: ~
      • {opts}  (`table`) Socket paths.  See |nauvim-plugin-paths|.
                • {client_socket_path} (`string`) Client socket path.
                • {host_socket_path} (`string`) Host socket path.

    Return (multiple): ~
      • (`integer?`) Forwarding handle.
      • (`string?`) Request error.

get_port({opts})		      *nauvim-plugin.local-forward.get_port()*
    Waits for TCP binding and returns the assigned client port (1..65535). A
    socket-forward handle or an unknown handle produces a request error.
    Clearing a pending forward completes a waiting call with `nil, nil`.

    Parameters: ~
      • {opts}  (`table`) Table with a `{handle}` field (`integer`).

    Return (multiple): ~
      • (`integer?`) Assigned client port.
      • (`string?`) Request error, including a binding failure.

clear({opts})				 *nauvim-plugin.local-forward.clear()*
    Sends a notification to cancel pending binding or close the listener.
    A created client socket pathname is removed.  Unknown handles have no
    effect.  Whether already accepted streams are closed is unspecified.

    Parameters: ~
      • {opts}  (`table`) Table with a `{handle}` field (`integer`).

Binding and forwarding failures are client errors.  Asynchronous binding
failures are reported by |nauvim-plugin.local-forward.get_port()|, including
failures already displayed in the client.

FILESYSTEM					    *nauvim-plugin-filesystem*

Use `require('nauvim-plugin.filesystem')`.

copy({opts})				     *nauvim-plugin.filesystem.copy()*
    Requests an asynchronous host-to-client copy.  Source symlinks are
    resolved.  Regular files and directories are copied, and other source
    types are ignored.  Directories are copied recursively.

    An existing destination of the same type is preserved when `{override}` is
    `false`.  With `{override}` set to `true`, files are overwritten and
    directories are deleted before recursive copying.  A mismatched
    destination type or an existing destination symlink is a client error for
    either value of `{override}`.

    Client-path validation errors are request errors.  The client displays
    copy and filesystem I/O failures separately from the RPC response.

    Parameters: ~
      • {opts}  (`table`) Copy options.  See |nauvim-plugin-paths|.
                • {client_file} (`string`) Destination path in the client.
                • {host_file} (`string`) Source path on the host.
                • {override} (`boolean`) Replace a destination of the same
                  type.

    Return (multiple): ~
      • (`integer?`) Copy handle.
      • (`string?`) Request error.

clear({opts})				    *nauvim-plugin.filesystem.clear()*
    Sends a notification to stop or cancel copying before deleting its client
    destination, including partial output.  This preserves an existing
    destination that was skipped because `{override}` was `false`.  Unknown
    handles have no effect.  A deletion failure ends the attempt.

    Parameters: ~
      • {opts}  (`table`) Table with a `{handle}` field (`integer`).

Detachment applies the same destination preservation rules after stopping copy
work. Distinct copies or cleanup operations with identical destinations or
ancestor/descendant destinations have undefined behaviour.

HTTP AND GUI PREVIEWS					  *nauvim-plugin-http*

Use `require('nauvim-plugin.http')`.

serve_file({opts})			     *nauvim-plugin.http.serve_file()*
    Requests an asynchronous server on 127.0.0.1.  The client path must name
    an existing regular file or directory or a symlink resolving to one.

    HTTP/1.1 supports plain HTTP and HTTPS.  HTTP/2 requires HTTPS.  Core
    returns a request error for plain HTTP/2 before starting the server.
    Startup failures are displayed in the client and can be queried with
    |nauvim-plugin.http.get_port()|.

    Parameters: ~
      • {opts}  (`table`) Server options.
                • {client_file} (`string`) Path to serve.  See
                  |nauvim-plugin-paths|.
                • {client_port} (`integer`) 0 to 65535.  Zero requests an
                  available port.
                • {https} (`boolean`) Use TLS with a self-signed certificate.
                • {http2} (`boolean`) `true` selects HTTP/2 and `false`
                  selects HTTP/1.1.

    Return (multiple): ~
      • (`integer?`) Server handle.
      • (`string?`) Request error.

get_port({opts})			       *nauvim-plugin.http.get_port()*
    Waits for binding and returns the assigned server port (1..65535) or a
    binding error.  Unknown handles and handles for other resource types
    produce request errors.  Clearing pending startup completes a call with
    `nil, nil`.

    Parameters: ~
      • {opts}  (`table`) Table with a `{handle}` field (`integer`).

    Return (multiple): ~
      • (`integer?`) Assigned server port.
      • (`string?`) Request error, including a binding failure.

open_webview({opts})			   *nauvim-plugin.http.open_webview()*
    Requests an asynchronous GUI window accessing an HTTP(S) URL, including a
    fragment identifier.  The URL is resolved in the client environment.
    Other URL schemes produce a request error.

    A request for a nonexistent grid returns a handle without opening a
    window.  For an existing grid the position must fit within the grid.
    Behaviour for an out-of-grid position is undefined.  The presentation
    component accepts self-signed certificates from
    |nauvim-plugin.http.serve_file()|.  The client displays GUI creation and
    access failures.

    The window receives focus when it opens if both focus flags are `true`.
    Setting `{focus}` to `true` and `{focusable}` to `false` is valid and
    skips automatic focus.  The meaning of focus depends on the UI.

    The host policy must permit the URL's origin.  Nauvim also checks the
    origin of each top-level navigation and redirect.  It blocks any denied
    navigation and reports an error in the client.  See
    |nauvim-plugin-host-permissions|.

    Parameters: ~
      • {opts}  (`table`) Preview options.
                • {url} (`string`) HTTP(S) URL.
                • {position} (`table`) Position in Neovim grid cells.
                  • {grid} (`integer`) Grid ID.
                  • {top} (`integer`) Offset down from the top, 0 to 65535.
                  • {left} (`integer`) Offset right from the left, 0 to 65535.
                  • {height} (`integer`) Height, 0 to 65535.
                  • {width} (`integer`) Width, 0 to 65535.
                • {focus} (`boolean?`) Request focus when the window opens.
                  Defaults to `true`.
                • {focusable} (`boolean?`) Allow the window to receive focus.
                  Defaults to `true`.

    Return (multiple): ~
      • (`integer?`) Window handle.
      • (`string?`) Request error.

focus_webview({opts})			  *nauvim-plugin.http.focus_webview()*
    Sends a notification to focus an open, focusable window created by
    |nauvim-plugin.http.open_webview()|.  A handle without a matching window
    has no effect and produces no error.  If moving focus fails, Nauvim
    reports an error in the client and leaves the window open.

    Parameters: ~
      • {opts}  (`table`) Table with a `{handle}` field (`integer`).

    Return: ~
      • (`nil`)

clear({opts})					  *nauvim-plugin.http.clear()*
    Sends a notification to cancel pending server startup or close an existing
    server or GUI window.  Unknown handles have no effect.  A GUI window
    request whose window does not yet exist is unaffected.

    Parameters: ~
      • {opts}  (`table`) Table with a `{handle}` field (`integer`).

CLIPBOARD					     *nauvim-plugin-clipboard*

Assign the provider before Neovim initializes clipboard integration. >lua

    vim.g.clipboard = require("nauvim-plugin.clipboard").provider
<
The provider copies `"+"` and `"*"` to the client system clipboard.  It needs
no external host program and does not cache clipboard data.  The client's
configured clipboard backend determines availability. Backend errors are
reported in the client.

Use `require('nauvim-plugin.clipboard')` for direct copying.

copy({opts})				      *nauvim-plugin.clipboard.copy()*
    Sends a notification to copy text.  Returns `nil` without waiting for the
    backend operation to complete.

    Parameters: ~
      • {opts}  (`table`) Clipboard options.
                • {register} (`string`) Either `"+"` or `"*"`.
                • {text} (`string`) Text with LF line separators and an
                  optional trailing LF.

The Neovim copy callbacks take `{lines}` and `{regtype}` and join the lines
with LF.  A trailing empty line preserves a trailing LF.  Without a selected
destination, `copy()` and its callbacks return `nil` without sending RPCs.

Clipboard-register reads supply no text.  Both provider paste callbacks take
no arguments, return a fresh `{ {}, "v" }` pair and issue no RPC.  This
behaviour is the same with or without a selected destination.

For GUI paste, nauvim-core obtains text from the client clipboard backend and
sends it to the host Neovim with |nvim_paste()| or an equivalent paste-input
operation.  See |provider-clipboard| and |provider-paste|.

CLIENT AND DESTINATION					*nauvim-plugin-client*

Use `require('nauvim-plugin.client')`.

connect({opts})				      *nauvim-plugin.client.connect()*
    Sends the host alias to the selected client, then immediately executes
    |:detach| without waiting for an acknowledgment.  Nauvim handles the
    welcome page and new connection.  If sending fails, an error is displayed
    without detaching, retrying or changing the stored destination.

    Parameters: ~
      • {opts}  (`table`) Table with a `{host}` field (`string`) for the
                client-side Nauvim host alias.

setup({opts})					*nauvim-plugin.client.setup()*
    Internal entry point used by Nauvim after UI attachment.  Only attached
    UIs with `client.name` equal to `nauvim-client-{client_id}` can be
    selected.  The decimal ID has no leading zeros.  If several match, one
    is selected.

    Successful setup replaces the single stored channel/client-ID pair without
    detaching any UI.  Failure clears both identifiers and returns silently.
    |UILeave| clears both when `v:event.chan` equals the selected channel.

    The plugin attempts each send using the stored channel ID.  A stale
    channel uses ordinary RPC error handling and remains selected until
    `setup()` or |UILeave| changes it.

    Parameters: ~
      • {opts}  (`table`) Table with a `{client_id}` field (`integer`) in
                the unsigned 32-bit range 0 to 4294967295.

Available operations depend on nauvim-core's enabled features and policies.
An unavailable request is an ordinary request error. Client registration and
session switching are always included in nauvim-core.
